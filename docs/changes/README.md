# 修改方案规范

当前生效修改方案为 [CHANGE-001：V1 优化方案 v0.2](2026-10-05-01-v1-optimization.md)及[CHANGE-002：GitHub / Windows 发布](2026-10-08-02-github-windows-release.md)，均由用户明确要求实施。有效方案与状态以 [CURRENT_PLAN.md](../CURRENT_PLAN.md) 为准。后续发生实质调整时，按以下规则记录。

## 文件与生效方式

- 文件名：`YYYY-MM-DD-序号-简短主题.md`，例如 `2026-10-10-01-task-recovery.md`。
- 状态：草案 / 生效 / 已被替代。
- 每份修改方案指明所基于的开发方案版本；生效时更新 `docs/CURRENT_PLAN.md`，并记入 `docs/CHANGELOG.md`。
- 新要求来自用户明确指示时，按该指示直接更新已授权内容。需要用户选择的未知事项保持待确定，不伪造确认。
- 同一要求尽量回写当前开发方案；若作为独立补充保留，必须写明覆盖哪些章节，避免两个权威来源冲突。
- 已被替代的文件保留作为历史，不再参与实施。

## 可复制模板

```markdown
# 修改方案：主题

日期：YYYY-MM-DD（Asia/Shanghai）
编号：CHANGE-XXX
状态：草案 / 生效 / 已被替代
基于方案：路径与版本
覆盖章节：具体章节；没有则写“补充”
来源：用户要求、实际问题或技术验证

## 目标与原因
说明具体问题，以及修改后期望的行为。

## 行为变化
旧行为：……
新行为：……

## 实施范围
受影响的功能、接口、数据、依赖与文档。
明确不在本次范围内的事项。

## 执行步骤
1. ……
2. ……

## 数据与兼容
是否迁移、如何保留历史项目、是否影响运行中任务。

## 验收与验证
可观察的通过条件、测试方法、实际验证结果。

## 风险与回退
费用、数据损失、兼容风险及具体回退步骤。

## 生效与交接
生效依据、索引更新、遗留事项和下一步。
```
