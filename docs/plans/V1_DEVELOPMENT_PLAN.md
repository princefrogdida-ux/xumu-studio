## 1. 目标与成功标准

开发一款面向单人短剧创作者的无限画布工作台，在一个项目里管理剧本、角色、场景、分镜图片与镜头视频。使用成熟画布库，自建短剧业务、素材存储与生成任务系统。

参考产品为 LibTV，但仅借鉴业务场景和可观察交互。公开首页已核实存在画布以及图片、视频、音频、剧本生成和智能剪辑入口；登录后编辑器尚未核实。本方案描述的是本项目要实现的功能，不宣称是 LibTV 的完整复刻或内部设计。

### 1.1 V1 必须跑通的闭环

1. 创建项目并输入一段剧本。
2. 手动建立分镜，或调用文本服务生成可编辑的结构化分镜草稿。
3. 上传角色、场景参考图，在多个分镜中复用。
4. 在画布中创建图片生成节点，引用分镜描述和参考素材。
5. 生成多个图片候选，人工选择一个用于后续视频生成。
6. 生成镜头视频，保留参数、状态与历史结果。
7. 刷新页面或重启应用后恢复项目；不丢失已保存内容，不重复提交生成请求。
8. 按镜头顺序导出选定视频、参考图片和分镜说明。

验收样例：一个项目，3～5 个分镜，至少一个角色跨两个镜头复用，至少一个镜头经过重新生成与版本选择，最终导出按编号组织的素材包。

模拟闭环与真实闭环分别验收。只有接入真实文本、图片、视频服务且实测成功后，才能宣布 V1 真实生成流程完成。

### 1.2 V1 不包含

- 完整非线性剪辑器、转场、混音、字幕编辑和一键成片。
- 多人协作、实时同步、账号权限、订阅计费及公网部署。
- 自主执行整集制作的 AI Agent、任意循环工作流、自动大规模批量付费生成。
- 原 V1 不含 Windows 安装包；V1.7 按用户要求增加本地浏览器版安装程序，移动端完整编辑体验仍不包含。
- 训练模型或保证跨镜头角色完全一致。

V1 的“导出”是有序素材交付，不等同于导出已剪辑的完整影片。后续增加成片合成需单独更新方案。

## 2. 默认约束与待确定事项

| 项目 | V1 默认选择 | 调整条件 |
|---|---|---|
| 用户与运行方式 | 单人、本地服务、浏览器界面 | 团队或公网使用须补账号与部署设计 |
| 平台 | Windows，桌面版 Edge / Chrome | 其他环境按实际验证补充 |
| 技术路线 | 画布库 + 自建业务 | 完整开源项目经代码和许可证审查后再决定是否替换 |
| 画布 | React Flow | 特殊手绘或自由图形需求增加时再评估 |
| 生成触发 | 用户点击单个节点生成 | V1 不自动执行下游链路 |
| 数据 | 服务端 SQLite + 本地媒体目录 | 上云或多人并发时再评估数据库与对象存储 |
| 文本/图片/视频服务 | 每类配置一个中转服务与模型，统一适配层 | 使用通用协议；具体中转站、能力与费用待核实 |
| 生成费用 | 默认模拟；真实调用需已有明确额度授权 | 不能把等待回复视为授权 |
| 镜头顺序 | 分镜编号与排序字段 | 与节点在画布的坐标分离 |

用户已明确选择中转站，并授权通用兼容适配及本地测试；本轮不调用收费接口。待确定项：具体地址与模型；结构化输出、参考图及视频协议能力；费用额度；素材保存期限；编辑器参考截图。适配代码可先完成，未实测前不宣称兼容某家服务或“大部分中转站”。

## 3. 主要页面与使用流程

### 3.1 项目列表

- 新建、打开、重命名、复制项目。
- 显示项目更新时间和基本缩略信息。
- 删除项目必须有明确确认；可实现软删除，V1 不主动清理媒体原文件。
- 复制项目生成新节点 ID，保留素材引用和镜头配置，不复制运行中任务，不自动生成。

### 3.2 画布工作台

- 顶栏：项目名、保存状态、适配内容、导出入口。
- 左侧：添加节点、素材库、角色与场景列表。
- 中间：画布、节点、连线、缩略图和生成状态。
- 右侧或浮层：选中节点的提示词、输入、模型参数和生成历史。
- 分镜列表面板：按剧情顺序查看镜头，选择输出版本；顺序不依赖画布排列。
- 任务面板：当前及历史任务，提供查看错误、重新查询和重试入口。

UI 默认中文。生成按钮清楚展示模拟/真实模式；等待、失败、无结果和未配置服务必须有明确状态。

### 3.3 操作约定

- 拖空白区域平移；滚轮或触控板缩放；提供明确的画布操作提示。
- 卡片拖动与文本编辑互不抢占输入事件。
- 常用快捷键：删除、复制粘贴、撤销重做、适配内容；输入框获得焦点时保留正常文本操作。
- 大图使用缩略图；视频先显示封面，仅在明确播放时加载，不同时自动播放全部节点视频。

## 4. 功能需求与验收

### 4.1 画布基础（CANVAS）

- 平移、缩放、适配全部节点、恢复保存的视角。
- 创建、重命名、移动、调整尺寸、删除节点。
- 单选、框选、多选移动；复制粘贴时重建节点 ID 和所选内部连线。
- 删除节点时移除关联连线；保留生成历史与素材记录，不连带删除磁盘文件。
- 撤销重做覆盖节点创建/删除/移动、连线和可编辑配置；一次拖动记为一次操作。
- 撤销不能取消远端生成、回退任务结果或重新触发收费请求。

验收：建立至少 20 个节点并连接，完成框选、复制、删除与撤销；刷新后位置、内容、连线和视角恢复一致。

### 4.2 剧本与分镜（STORY）

- 剧本文本可直接编辑；分镜无需 AI 也可以手工建立。
- AI 拆解返回结构化草稿，用户预览后应用，不能直接覆盖现有分镜。
- 字段：镜头编号、排序、场景、角色引用、画面描述、景别、动作、运镜、对白、预计时长、图片提示词、视频提示词。
- 提供字段校验；无效模型响应保留原始失败信息，不生成残缺镜头。
- 再次拆解默认生成新的草稿，用户选择替换或追加；替换前保留旧版本或可回退快照。
- 分镜行和画布分镜节点引用同一份 Shot 数据，避免两个独立副本。

验收：手工与模拟 AI 两种方式均可创建 3～5 个镜头；调整顺序后导出顺序相同，画布位置不改变排序。

### 4.3 角色、场景和素材（ASSET）

- 角色与场景记录包含名称、描述、参考图片列表及默认选中参考图。
- 上传图片和视频；按项目展示素材并允许重用。
- 支持缩略预览、视频播放、单文件下载、文件类型和大小校验。
- 同一素材使用稳定 ID 引用，不把临时浏览器 URL 当成持久化地址。
- 角色参考图变更只更新后续输入，不覆盖已生成素材；引用新版本的节点标记输入已变化。
- 素材缺失或损坏时显示明确错误，并阻止依赖它的生成或导出。

验收：上传参考图，关闭并重启应用后可预览；多个分镜共享同一角色素材；更新参考图后旧输出仍可查看。

### 4.4 图片生成（IMAGE）

- 支持提示词、参考图、模型、比例及模型实际支持的参数。
- 接收连线输入；提交前展示本次使用的文字、图片和参数摘要。
- 每次任务固定输入快照，运行中编辑节点不能改变已提交任务。
- 保存每次候选结果；明确选择哪一版供下游使用。
- 不承诺所有模型支持多参考图、负面提示词或固定随机种子；根据适配层能力展示。

验收：同一节点生成两次并保存历史；切换选中图片后，下游输入更新但不自动生成。

### 4.5 视频生成（VIDEO）

- V1 重点支持图生视频：选定图片 + 视频提示词 + 可用模型参数。
- 时长、分辨率和比例根据真实服务能力校验；文生视频等扩展按能力决定。
- 显示等待、运行、失败、待确认、成功等状态，生成成功后可预览和下载。
- 保留多个镜头视频版本及选中版本。

验收：视频任务可在刷新后继续查询；生成完成后能播放；导出使用人工选定版本。

### 4.6 保存与恢复（SAVE）

- 服务端数据库是最终持久化来源；浏览器缓存可作为恢复草稿，不替代后端保存。
- 编辑后防抖保存，目标约 1 秒；拖动结束时保存最终坐标。
- 保存状态至少区分保存中、已保存、失败、未同步更改。
- 使用递增 revision 校验，旧请求不能覆盖新状态；冲突不静默覆盖，提示重新加载或保留草稿。
- 后端保存失败时保留本地草稿，恢复连接后由明确规则处理，不伪装成功。
- 项目数据包含 schemaVersion；迁移失败保留原数据，不清空项目。

验收：快速连续编辑并刷新不丢失已确认保存内容；模拟保存失败有错误提示；乱序保存和多标签编辑不会静默覆盖。

### 4.7 导出（EXPORT）

- JSON 导入导出：仅项目结构、配置和素材引用；清楚提示不自带媒体原文件。
- 素材包导出：按镜头顺序打包选定图片/视频，附 `storyboard.csv` 和 `manifest.json`。
- 文件名含镜头编号；原始镜头 ID 写入清单，防止重名。
- 清单保留提示词、生成模型标识、参数、版本和素材来源；不包含密钥、令牌或敏感远端凭证链接。
- 有镜头未选择视频、文件丢失或任务未完成时，列出具体缺失项，不能悄悄导出不完整结果。允许用户明确选择只导出已有素材。
- JSON 导入先校验版本、大小、节点类型、唯一 ID、引用和连线；导入为新项目，不覆盖当前项目，不执行任务，不自动抓取未知远端 URL。

验收：素材包解压后文件齐全、编号与分镜顺序一致；JSON 导入可恢复结构并提示缺失的外部素材。

## 5. 节点模型与连线规则

### 5.1 V1 节点类型

| 节点 | 内容或输入 | 输出 | 是否调用模型 |
|---|---|---|---|
| Text | 手写文本、剧本或提示词 | 文本 | 否 |
| Script | 剧本和拆解设置 | 分镜草稿，用户应用后生成 Shot | 点击拆解时调用文本服务 |
| Reference | 引用角色、场景或上传素材 | 选中参考图片 | 否 |
| Shot | 镜头描述、角色/场景引用 | 图片提示词、视频提示词 | 否 |
| ImageGenerate | 文本、参考图片、参数 | 选中图片资产 | 点击生成时调用图片服务 |
| VideoGenerate | 选中图片、文本、参数 | 选中视频资产 | 点击生成时调用视频服务 |
| Media | 引用已上传或生成的图片/视频 | 对应类型素材 | 否 |

角色和场景是独立业务记录，Reference 节点只是它们在画布上的引用。模型生成结果是 Asset，不能仅保存在节点临时状态里。

### 5.2 连接与输入解析

- 端口类型包括 text、image、video；禁止不兼容连接。
- V1 以无环数据引用图实现，禁止自连接、循环、重复边和跨项目引用。
- 文本主输入仅一个连接；参考图片允许多个连接但不得超过模型能力。需要拼接多个文本时，先在 Text 节点明确整理，不隐式合并。
- Shot 提供不同文字输出端口，区分图片提示词与视频提示词。
- 已连接文本作为基础输入，节点内补充提示词作为后缀；提交前显示拼接结果。未连接时直接使用本地提示词。
- 图片输入存在连线时使用该连线选定的资产；参考图片按显式顺序解析，不能依赖渲染顺序。
- 上游尚未选中有效结果时，阻止下游生成并解释原因。
- 连线只建立依赖，不提交任务。用户明确点击生成才创建任务；批量自动执行留待后续版本。
- 上游改变后，下游已生成结果标记“输入已变化”，保留旧结果。基于旧输入的历史输出仍可人工选用，并明确标识来源。

## 6. 技术架构与目录

### 6.1 基线技术选择

| 层 | 方案 | 理由与边界 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 适合组件化画布与独立后端 |
| 画布 | React Flow（`@xyflow/react`） | 自定义节点和有类型连线 |
| 编辑状态 | Zustand 或小型明确的状态层 | 将画布编辑与任务状态分开 |
| 校验 | 共享 TypeScript 类型 + Zod | 统一导入、接口和模型结果校验 |
| 后端 | Node.js + TypeScript + Fastify | API 与模型适配层使用同一语言 |
| 数据 | SQLite，Node.js 24 内置 `node:sqlite`，显式迁移 | 已在 Windows 验证；当前运行时有实验特性提示 |
| 媒体 | 本地项目数据目录 + 缩略图 | 数据库保存元信息，不存大段 Base64 |
| 任务 | 数据库持久化任务 + 独立 worker 进程 | 页面关闭不影响执行；V1 不引入 Redis |
| 测试 | 单元/接口测试 + 浏览器关键流程 | 具体工具在 M1 锁定并实测 |

M1 已将前端、画布、状态、校验和后端依赖固定在 `package.json` 与 `pnpm-lock.yaml`。使用 pnpm 11.19、Node 24.14、Zustand；测试使用 Node test runner + tsx，浏览器通过实际 UI 验证。M2 使用 sharp 0.35.5（Apache-2.0）解码图片并生成 WebP 缩略图，已核实官方 Windows 预编译支持；允许其安装脚本。M3 已加入独立 worker；真实模型适配在 M4 推进。升级依赖时复核官方文档、许可证和 Windows 兼容性。

M3 增加独立 Node worker 和数据库任务系统。M4 复用现有依赖和 Node 内置 HTTP、HTTPS、DNS 实现中转协议，无新增包或依赖升级。

M5 新增并固定 yazl 3.3.1（MIT）及开发类型声明 @types/yazl 3.3.0。已核实官方流式接口、路径规则、许可证并在 Windows 实测 ZIP 解压；不升级既有依赖。

### 6.1.1 M2 媒体实现约束

- 静态 PNG、JPEG、WebP：单文件最多 20 MiB，最多 4000 万像素；扩展名、MIME 与实际解码格式必须匹配。缩略图最大 640 × 480，保留比例且不放大小图。
- MP4、WebM：单文件最多 100 MiB，校验容器标识/结构；能否解码由浏览器播放器判断，不承诺任意编码兼容，不做转码。
- 素材保存到数据目录的 `media/`，内部文件名采用 UUID；API 不暴露物理路径。原文件保存 SHA-256，读取原文件/缩略图前检查原文件完整性；列表只检查存在性与大小，同大小损坏会在预览或下载时发现。
- 视频提供 Range 响应，画布使用通用封面，素材库与属性面板点击后才加载播放器。M2 不提取视频帧或服务端时长。
- 上传采用二进制请求体，不安装 multipart 插件；单次请求受大小限制，界面多文件逐个上传。资产列表与单文件下载已实现，ZIP 素材包在 M5 实现。
- 文件先临时写入再改名，再保存数据库记录；普通失败清理该上传产生的文件。进程强制终止可能留下孤立文件，V1 不自动删除。

### 6.1.2 M3 模拟与任务实现约束

- 节点类型在代码中为 `script`、`imageGenerate`、`videoGenerate`；默认模型为 `mock-script-v1`、`mock-image-v1`、`mock-video-v1`。M3 交付时只有模拟模式；M4 增加独立中转模式，旧节点仍默认模拟。
- 图片模拟按请求比例生成带 MOCK / NO AI GENERATION 标识的本地几何 PNG，候选 1～4 张、参考图最多 8 路。视频要求一张有效首帧，输出随源码附带的 MDN CC0 测试片段；提示词、请求比例和 1～10 秒时长仅验证及留存快照，不合成符合这些参数的视频。
- 剧本模拟按文本分句形成 3～5 条严格校验的草稿，不是 AI 理解。用户预览后追加或替换；应用作为一次编辑进入撤销历史，任务与草稿结果保持独立。
- 前后端使用同一纯输入解析规则。服务端额外校验图片归属、存在性与 SHA-256；提交要求当前 revision 与已检查摘要的 fingerprint 相符。快照只保留实际提示词、稳定图片 ID、模型、有效参数及模拟异常场景；内容用 SHA-256 标识。
- `dev` 同时启动 API、Vite 与独立 worker。生产 `start` 只启动 API，另开终端执行 `worker`。浏览器每约 1.2 秒读取任务状态，不执行生成。
- worker 默认全局并发 1，租约 15 秒、执行期间约每 5 秒续租；数据库锁与状态比较防止多个进程同时认领或失效 worker 写入。正常模拟等待约 5 秒，查询间隔约 1 秒；查询/保存最多 3 次错误后转为待确认/明确失败。
- 失效的 submitting 租约没有远端 ID 时进入 unknown，有 ID 时恢复查询。MockProvider 以任务 ID 建立持久化模拟远端记录；只有明确“重新查询”才按 ID/请求标识找回。该能力仅限本地模拟，不能推断真实服务支持同样的查找。
- 保存中断后按任务与候选序号复用已写入的资产；保存失败的“重新查询”只恢复查询和落盘。生成历史与成功状态在同一数据库事务发布；结果不会自动选中。
- 版本选择作为项目编辑通过 revision 保存，不另建自动生成动作。“设为镜头选用”同一次编辑同步节点版本和 Shot 素材。复制项目不复制任务/生成历史，保留授权素材与选用资产；复制节点清除原节点的 generation ID，保留稳定资产引用。
- 客户端发送前留存 requestKey，网络结果不明时用相同请求确认；worker 的 unknown 不自动重交。模拟异常支持明确失败、提交响应丢失、查询超时、无效分镜响应。

### 6.1.3 M4 中转适配实现约束

- 文本、图片、视频各自配置服务端地址、密钥和模型，采用 Bearer 鉴权；没有默认真实服务商或模型。生产配置只接受 HTTPS。缺失或非法配置明确禁用该类服务，不影响其他类型和模拟模式。
- 文本通过非流式 `POST /chat/completions` 获取 `choices[0].message.content`；默认用提示词约束 JSON，可明确配置 `json_object` 或 `json_schema`。严格校验 3～5 个镜头及请求数量；无效响应只保留脱敏诊断，不自动应用分镜或重新生成。
- 图片通过 `/images/generations`；有参考图时使用 `/images/edits`，明确选择 JSON `images:[{image_url:data-url}]` 或 multipart `image[]`。不通过失败后换协议来重复提交。默认不假定参考图能力，候选默认 1；按已核实能力配置参考图 0～8、候选 1～4。
- 图片参数使用显式比例→实际尺寸映射；默认提供 1:1、3:2、2:3，不能将 1536×1024 标为 16:9。能力校验在前后端重复执行；任务快照固定实际 size。参考图以本地文件内容发送，不向中转站提供本机素材 URL；总参考图不超过 30 MiB。
- 视频没有跨中转站统一标准，使用服务端受限 JSON 模板配置提交/查询路径、输入字段、任务 ID/状态/结果路径与状态值。只适配 Bearer + JSON 提交、单张 data-url 首帧、字符串 ID、GET 轮询、单个 MP4 下载地址。模板不执行脚本；multipart、必须公网首帧 URL、额外参数或特殊鉴权需要专用适配。
- `STUDIO_REAL_CALLS_ENABLED` 默认 false。API 创建任务与 worker 执行均检查开关；配置预览、刷新状态、连线、选版本和切换模式不触发生成。本轮运行保持 false；此开关不是额度计费系统，费用未知时如实显示。
- 每份真实快照包含 mode、provider、model、serviceId、实际参数与稳定素材 ID。serviceId 是端点、协议和能力配置的摘要，不包含密钥；关键配置变化后阻止使用新服务执行旧任务。切换配置不能无提示地改投新的模型；恢复原配置后可查询历史任务。
- 同步输出、异步远端 ID 和签名地址先保存在服务端私有 `provider-results/` 回执；Base64 媒体写为二进制文件，不写入 SQLite 或浏览器。公开任务 ID 为本地 `relay:<任务 UUID>`，API/结构导出不暴露原始远端 ID、签名地址、鉴权或物理路径。
- 本地 requestKey 仅保证本地去重，不假定中转站支持远端幂等。收费 POST 不自动重试；响应丢失且无已保存回执时进入 unknown，明确重新查询也不能凭空找回远端任务，须人工核实。已有私有回执可明确恢复，下载中断复用已保存候选，不重新生成。
- 查询/下载失败按既有最多 3 次规则停止；未映射视频状态进入 unknown。明确重试创建新任务并提示可能产生费用。关闭真实开关会阻止远端查询和下载，重新开启后需要检查待确认/失败状态并明确恢复。
- URL 媒体必须配置精确主机允许列表，每次请求及重定向均检查 HTTPS、DNS 公网地址并固定解析结果；拒绝本机/内网/保留地址，最多 3 次重定向、不转发 API 鉴权。图片不超过 20 MiB、视频不超过 100 MiB，再用已有媒体校验落盘；成功以资产与历史事务发布为准。
- 界面区分当前运行模式、上次任务模式、历史输出来源和已选素材来源，不能因切换到真实模式将旧模拟结果重新标为真实。

配置操作见 [M4_CONFIGURATION.md](../M4_CONFIGURATION.md)，实际接口见 [M4_API.md](../M4_API.md)，验证证据见 [M4_VALIDATION.md](../M4_VALIDATION.md)。真实服务、效果和费用仍待实测，V1 真实闭环标准保持不变。

### 6.1.4 M5 导入与素材交付实现约束

- 用户本轮明确启动 M5，优先于旧索引“不启动 M5”的阶段安排。M4 真实服务未验收不阻止本地导入/交付开发；真实调用保持关闭，完整 V1 真实闭环标准不变。
- JSON 格式 `drama-studio-structure` / formatVersion 1，包含名称、document、sourceProjectId、素材元信息引用和说明，最多 2 MiB。兼容旧 M1～M4 `{name,document,note?}` 快照；未知格式/文档版本、重复 ID、无效节点、业务引用、素材类型和非法连线拒绝导入。
- 导入事务创建新项目，重建节点、边、角色/场景和镜头 ID，保留顺序、视角、配置及选用素材；清除 selectedGenerationId，不创建任务、不导入任务历史、不读取客户端路径或获取远端 URL。
- 同一数据目录中，只复用 sourceProjectId 已关联且元信息匹配的素材。外部或缺失素材建立新 UUID 的本地缺失记录并重写引用，提示上传替换；保持项目可编辑、可保存，依赖缺失素材的生成/导出继续受校验阻止。旧快照未提供素材清单时按引用类型建立缺失记录。
- M5 交付时文档和数据库为版本 4（V1.6 后续 DB5、文档仍 4）；缺失记录复用 assets / project_assets，不改写旧项目、任务快照或原文件。JSON 不是完整媒体备份；ZIP 不包含数据库任务和私有回执，也不是完整备份。
- 素材包包含按 Shot.order 排列的最终选用图片/视频、角色/场景参考图、UTF-8 BOM `storyboard.csv` 与 `manifest.json`。镜头目录及文件名都含剧情序号、清理后的镜头编号、原镜头 ID 的摘要；清单保留完整原镜头 ID，重复编号不会覆盖。
- 清单固定 revision、镜头内容与选用资产，保留 SHA-256、素材来源及可获得的生成 task/generation ID、候选序号、实际提示词、模型和参数。仅序列化公开字段，不导出 providerTaskId、回执、服务端密钥、鉴权、远端凭证链接或物理路径。上传或外部导入没有可追溯任务时 provenance 为 null，不能补造历史。
- 检查缺少选用图片/视频、缺失/损坏文件及未完成/待确认任务；默认阻止不完整导出。用户明确勾选“仅导出已有素材”后，缺失镜头和问题仍写入 CSV/清单，不静默过滤。失败/取消的历史任务不阻止有效旧版本交付。
- 创建打包要求检查摘要 fingerprint 与 revision 匹配；异步检查期间项目变化时拒绝。yazl 流式写入 ZIP，媒体再次边读边校验，完成后原子发布；失败不提供半成品。原文件合计最多 1 GiB，同一媒体用于多个镜头按实际重复打包计入限制；单 API 实例一次一个素材包。
- ExportJob 用数据目录 `exports/<UUID>.json` 和 `.zip` 持久化，状态 building/succeeded/failed。刷新可找回最近一次下载；API 关闭等待当前打包，异常重启把 building 标成失败，不自动重建。不自动清理历史 ZIP 或孤立 .part 文件。磁盘满导致状态无法写入时本次 API 返回明确失败，重启后按中断处理。
- CSV 全部字段转义双引号，保留逗号与换行；可能被表格程序识别为公式的文字加单引号防护，manifest 保留原文。用户在可编辑文本中主动输入的内容按原文保留，自动脱敏边界针对服务端私有数据。

实际接口及操作见 [M5 导入导出](../M5_EXPORT_IMPORT.md)，证据见 [M5 验证记录](../M5_VALIDATION.md)，完整数据备份见 [备份恢复](../BACKUP_RESTORE.md)。

- M4 文档和数据库版本为 4；增加生成节点可选 mode（旧节点缺省为 mock）、真实服务 provider、serviceId 和实际 size、真实草稿 mode、`generated` 资产来源。事务迁移旧文档，不重写任务快照、fingerprint、历史或资产；私有回执独立于编辑数据。模拟快照保持 M3 JSON 形状，旧 fingerprint 不因本次升级失效。
- 升级前停全部服务备份完整数据目录；回退仍需旧代码与升级前数据配套。无首次 Git 提交，不宣称已具备一键代码回退。
- 共享参考和上游版本改变通过实际解析输入的 fingerprint 标记“输入已变化”，不会覆盖旧输出或自动创建任务。

- 使用稳定唯一 ID；引用必须存在且属于当前项目，跨项目复用需通过显式复制/引用设计，不直接猜路径。
- 素材、节点、任务和镜头分开保存，避免删除节点等于删除历史任务。
- 选中生成版本与 Shot 的选中素材通过单一应用动作同步；同一 Shot 可有多个生成节点，但修改最终镜头版本需明确“设为镜头选用”。
- 当前输入 fingerprint 与历史任务快照比较，判断结果是否基于旧输入。
- 输入快照只保存服务实际使用的参数和稳定素材 ID，不保存密钥或临时签名地址。
- 生成历史默认保留；V1 不自动清理孤立文件。未来清理须先统计引用并明确确认。

## 8. 生成服务与任务执行

### 8.1 服务适配接口

```text
getCapabilities() -> 支持的输入、参数、限制和查询能力
submit(inputSnapshot, requestKey) -> 即时结果或 providerTaskId
query(providerTaskId) -> 服务商状态与结果
cancel(providerTaskId) -> 仅在服务商支持时提供
normalizeError(error) -> 可操作的统一错误
```

MockProvider 与真实适配器使用同一内部接口。Mock 模式覆盖等待、成功、失败、超时和恢复；优先使用本地测试媒体，不产生真实收费。

### 8.2 任务状态

```text
queued -> submitting -> running -> persisting -> succeeded
queued/submitting/running/persisting -> failed（已确认失败）
submitting/running -> unknown（提交或远端状态无法确认）
queued -> cancelled（尚未提交，可确定取消）
```

- 同步服务可从 submitting 直接进入 persisting。
- `unknown` 表示待确认，不等于失败；不能因此自动重新提交。
- 浏览器刷新不创建新任务，轮询仅查询已有任务。
- 任务成功以输出媒体已落盘、资产记录已保存为准，不以远端返回链接为准。
- 运行中任务的远端取消仅在服务商支持时提供；不承诺退款或立即停止。

### 8.3 幂等与恢复

- 单次点击使用唯一 requestKey，重复 HTTP 请求返回同一任务；按钮禁用只是辅助，后端必须去重。
- requestKey 不等于服务商支持幂等。提交超时且缺少远端任务 ID 时，标记 unknown；先查询或人工核实，不盲目重发。
- worker 使用持久化认领/租约；失效租约恢复时区分尚未提交、已保存远端 ID 和提交结果未知三种情况。
- 已有 providerTaskId 时只恢复查询，不重复提交；文件下载失败优先重试下载，不重做生成。
- 查询和下载可按退避规则有限重试；收费提交不得因网络错误自动重试。
- 首版全局生成并发默认 1；轮询按服务商推荐间隔执行，不将未知远端进度伪装为准确百分比。
- 用户明确重试会创建新任务并关联前次任务，提示可能产生新费用；已有授权范围内无需重复确认每次正常生成。

### 8.4 费用与凭证

- 凭证通过服务端环境变量读取，提供不含真实值的 `.env.example`。
- 无配置时展示未配置状态，仍可使用 MockProvider。
- 真实调用前确认服务、能力与额度；不能捏造预估价格。
- 若服务商提供可靠费用信息，可展示预估；不提供时明确费用未知。
- 日志隐藏密钥、鉴权头、敏感 URL；导出仅保留安全的模型标识和参数。

## 9. API 规划

路径为设计草案，代码阶段保持功能语义并在实际 API 文档中更新。

| API | 用途 |
|---|---|
| `GET /api/health` | 后端可用性 |
| `GET/POST /api/projects` | 列表与创建 |
| `GET/PATCH /api/projects/:id` | 读取、重命名 |
| `PUT /api/projects/:id/document` | 校验 revision 后保存项目编辑数据 |
| `POST /api/projects/:id/duplicate` | 复制项目但不执行任务 |
| `POST /api/projects/:id/import` | 校验后导入为新项目 |
| `POST /api/projects/:id/assets` | 上传媒体 |
| `GET /api/assets/:id/file` | 按资产 ID 访问媒体，支持视频 Range |
| `GET /api/providers/capabilities` | 可用模型及支持参数，不返回密钥 |
| `POST /api/projects/:id/tasks` | 服务端解析节点输入、固定快照并创建任务 |
| `GET /api/projects/:id/tasks` | 查询任务状态 |
| `POST /api/tasks/:id/retry` | 明确创建重试任务 |
| `POST /api/nodes/:id/select-generation` | 选择输出版本 |
| `POST /api/shots/:id/select-assets` | 指定最终镜头素材 |
| `POST /api/projects/:id/exports` | 创建素材导出任务 |
| `GET /api/exports/:id` | 状态与下载信息 |

接口统一返回错误码、中文可操作说明和必要详情。任务创建在后端再次校验素材、图结构、参数与服务能力，不能仅信任前端校验。选择历史结果不属于收费任务。

M3 路径与请求示例见 [M3_API.md](../M3_API.md)，M4 能力与安全字段变更见 [M4_API.md](../M4_API.md)，M5 导入/素材包实际路径见 [M5_EXPORT_IMPORT.md](../M5_EXPORT_IMPORT.md)。节点版本/镜头素材选择目前通过项目文档 PUT 和 revision 校验统一保存；上表的独立选择端点仍是草案，不能当成已有 API。

## 11. 测试与质量标准

### 11.1 必测规则

| 场景 | 通过条件 |
|---|---|
| 类型不匹配、循环、重复连线 | 拒绝并解释原因 |
| 重复生成请求 | 相同 requestKey 只产生一个本地任务 |
| 提交超时、结果不明 | 状态 unknown，不自动重交 |
| 运行中更改提示词 | 当前任务快照不变，新结果显示来源 |
| 页面刷新与 worker 重启 | 已保存任务可恢复，不重复提交 |
| 上游版本切换 | 下游输入变化提示，旧输出保留，无自动生成 |
| 保存乱序或 revision 冲突 | 无静默旧数据覆盖 |
| 图/视频文件缺失 | 明确错误，不伪装完成 |
| 导出 | 只使用选定版本，顺序正确，不包含凭证 |
| JSON 非法导入 | 拒绝或提示，不覆盖当前项目，不执行任务 |
| 输入框快捷键 | 不误删节点，正常编辑文本 |

测试分为纯规则单元测试、数据库/API 集成测试和浏览器关键流程。真实模型测试是有额度限制的人工验证，不放入默认自动化测试。

### 11.2 性能检查目标

- 基本验收：20 节点流畅操作；扩展检查：100 个节点、约 150 条连线，无自动播放视频。
- 首轮在实际 Windows 机器上记录浏览器、屏幕分辨率、节点数、素材体积及可观察卡顿，再确定量化性能门槛。
- 画布外素材延迟加载；使用缩略图；任务轮询不重渲染全部节点。
- 性能是待验证目标，不承诺任意数量节点或“无限性能”。

### 11.3 数据与文件保护

- 上传检查 MIME/扩展名、大小和合法文件名；服务端存储路径使用内部 ID，不接受客户端任意路径。
- 生成结果下载仅处理受信任服务返回的地址，限制协议、重定向、大小与超时，避免访问本机或内网地址。
- 文件写入先临时文件后完成替换，数据库与媒体状态需要可恢复。
- 本地备份覆盖数据库与媒体目录；采用一致性备份方式，不能运行中直接复制单个数据库文件而忽略 WAL。恢复步骤先停服务，保留原数据备份再恢复。
- 不把 JSON 元信息导出称作完整媒体备份。

## 12. 主要风险与应对

| 风险 | 应对 |
|---|---|
| 角色跨镜头不一致 | 复用参考素材和参数，保留人工选择，不保证模型效果 |
| 服务能力差异 | 能力驱动参数面板，提交前验证 |
| 网络异常导致重复费用 | 本地幂等、远端状态确认、未知状态不自动重交 |
| 临时媒体地址过期 | 生成成功前下载到本地稳定存储 |
| 编辑与执行状态混在一起 | 编辑快照、任务和素材分层，撤销不回滚远端执行 |
| 多标签覆盖数据 | revision 校验与冲突提示 |
| SQLite 驱动 Windows 安装困难 | M1 先做兼容验证，选低安装负担驱动并锁定版本 |
| 大量视频拖慢画布 | 封面、延迟加载、限制并发播放 |
| 需求持续扩大 | 先验收 3～5 镜头闭环，新增能力走修改方案 |
| 参考产品信息不足 | 按当前自建设计推进，后续截图调整交互，不捏造功能 |
