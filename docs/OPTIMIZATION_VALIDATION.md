## 性能实测

同一 Windows 10.0.26200、Core Ultra 5 225H（14 逻辑处理器）、约 31.5 GiB 内存、Node 24.14.0。服务端基准为独立进程内存数据库，不含浏览器网络往返；前后各三次串行运行，每次首请求和 20 次热请求。浏览器为 IAB Chrome 154.0.0.0、1280×720，生产构建加相同轻量测量代码，100 节点/150 连线；测量本身有开销。源码旧基线保持原样，测量构建独立保存。

| 首请求三次中位数 | 146.759 ms | 15.376 ms |
| 60 次热请求中位数 / p95 | 134.160 / 157.658 ms | 0.711 / 1.249 ms |

## 浏览器业务核对

验证数据始终用独立副本：旧项目与旧候选可读；三镜头状态和最终选用来源正确；任务查看节点后切换画布并定位可见。准备新镜头的图片节点后重复操作没有重复节点/边，逐次撤销恢复原结构。

故意缺失的图片同时被角色、场景和 Media 引用，替代预览明确 checksum 不同；应用后引用一致，撤销恢复缺失，重新应用和保存通过，旧任务/共享项目不改写。替代预览截图（本地验收产物 `output/optimization/repair-preview.png`，不随源码发布）。隔离 worker 强停后，明确提交一次 Mock 任务，界面显示排队与心跳缺失；重启 worker 后同一任务完成、活动数归零。心跳截图（本地验收产物 `output/optimization/worker-stale-queued.png`，不随源码发布）。此故障操作为强制终止，不能称正常关闭；后续受控 worker IPC 停止退出码 0。

主服务于本轮收尾重新启动在 4310/4311，worker 在线、活动任务 0、真实开关 false。隔离测量 API 的旧辅助父进程没有交互 stdin，结束前核对无活动/打包任务，再强制结束已验证 PID；它们不计入正常停止证据。

最终 交付检查（本地验收产物 `output/optimization/delivery-check.json`，不随源码发布）再次核对启动后的原业务表、非数据库文件、旧代码/完整备份哈希、文档本地链接、真实配置关闭及全部隔离端口释放；当前源码/文档白名单指纹见 validated-code-hashes.json（本地验收产物 `output/optimization/validated-code-hashes.json`，不随源码发布），不含真实配置与运行数据。doctor 输出（本地验收产物 `output/optimization/final-doctor.log`，不随源码发布）、最终工作台截图（本地验收产物 `output/optimization/final-workspace.png`，不随源码发布）可用于后续核对。主服务会话保持运行；如后续服务已退出，按 README 重新启动。
